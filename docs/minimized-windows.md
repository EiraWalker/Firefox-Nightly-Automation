# 最小化窗口

最小化是窗口显示状态，不是 DOM、页面截图或 Remote Control 连接不可用的同义词。工具不再要求用户先手动取消最小化；界面控件是否可调用、窗口归属及被测应用的业务资格分别判断。

## 默认行为

- **服务已开**：直接连接，不为页面操作或截图恢复目标窗口。独立工作窗口在执行中最小化，也可以继续访问自己的文档和取页面图像。
- **服务未开**：原生面板需要显示时，只在既有 service-start 授权区间内临时恢复精确目标窗口；完成或失败时还原原来的最小化状态。窗口原本为最大化后最小化的，仍保留其最大化还原状态。
- **严格禁止激活**：当前任务明确禁止原生服务准备激活时，调用方只复用已开服务，不进入需要恢复/激活的启动路径。工作窗口创建期与原生确认框的授权分别遵循原规则。
- **工具维护**：修复和实机验收确需关闭重开 Remote Control 时，默认包含必要的短暂起停授权，不重复要求用户批准。先核对进程、服务代次及当前连接范围，最后恢复原来的服务开关状态；这不包含退出或重启 Firefox、刷新用户页面、清空数据或付费业务请求。普通页面任务不能据此重置其他会话。

用户其他窗口仍不被接管。工具不修改最小化页面的 `visibilityState`，不改变字幕插件“暂停、最小化或失去观看资格时停止新增付费请求”的规则。

## 窗口校验

`GetWindowRect` 在最小化时可能返回负数离屏占位坐标，因此不能只比较这组值并断言窗口已被移动。每个已观察窗口同时保留：

| 字段 | 含义 |
| --- | --- |
| `bounds` / `minimized` | 实际采到的外框坐标与最小化状态，原样保留 |
| `normalBounds` | Windows 保存的普通显示位置；普通顶层窗口使用工作区坐标，不能与屏幕坐标混用来移动窗口 |
| `restoredState` | 从最小化还原后应为普通或最大化 |

双方都有完整合法的窗口位置元数据时，校验正常位置和还原状态。仅最小化/还原及其占位外框变化不算位置失败；双方都非最小化时，实际外框仍必须相同。真实移动、缩放、普通/最大化转换、窗口集合、进程代次或生命周期标记变化仍失败。标签选择变化仅观察，不单独中断。

缺失元数据时保留原有保守比较；元数据存在但非法时返回 `window-placement-invalid`。观察不可用不是通过条件。锁定基线不会因最小化而重设，原始事件、快照及既有失败历史继续保留。

`windowGeometryStable` 和 `minimizedStateStable` 仍反映原始值是否相同；最小化前后它们可以为 false，而 `canonicalGeometryStable` 和作用域 `windowsStable` 为 true。工作窗口模式仍以已登记 owned HWND 的 `scopedWindowsStable` 为准，不能把原始全局字段一概解释成任务失败。

## 原生启动准备

启动准备只登记本次已核验窗口，绑定 PID、进程创建代次及随 HWND 销毁的原生属性标记。每次恢复、读回及收尾前都核对归属、正常位置和还原状态；选中标签差异保持原始诊断，不作为租约中止条件。

- `SW_RESTORE` 仅用于刚刚确认仍最小化的目标；它保留 Windows 的普通/最大化还原记录，并属于已经允许短暂激活的服务开启区间。
- `SW_SHOWMINNOACTIVE` 用于收尾；不写回位置、尺寸或 WINDOWPLACEMENT flags，不修改其他窗口。
- Windows 异步显示调用开始不表示目标状态已到达；实际状态须有界读回。
- 恢复请求尚未观察到执行时，即便当前窗口仍最小化，也不算收尾成功；保留未确认状态，不能声称已撤回排队的恢复请求。
- 用户已自行恢复、且本工具没有排入恢复请求的，不在收尾时替用户最小化。
- 窗口被关闭、HWND 被复用、进程代次变化或用户移动窗口时，不对变化后的目标执行收尾动作；保留具体错误，而不是强行恢复。纯切页仍可完成原有租约收尾，不改选中页。
- 原生动作已发出后不重放；准备收尾失败和原始失败分别保留，所有焦点区间都结束。

`background.serviceWindowPreparation` 保存 HWND、原最小化状态、恢复请求、状态读回、收尾完成与固定错误码；停止状态观察准备另记 `purpose=stopped-state-observation`。`restoredOriginalState=true` 是读回事实；`active=false` 表示租约结束，不单独证明启动、握手或整次任务通过。

worker 被硬杀、崩溃或 Windows/Firefox 长期无响应时，finally 不保证有机会运行；缺少收尾读回只能报告原状未确认，不能把超时、传输关闭或退出当作已还原。保留已确认的进程/窗口归属和失败收据，不通过重启浏览器掩盖未完成的收尾。

## 本次原生 Allow 收尾

Allow 可能由 Firefox 自行还原父窗口。工具在最终 Invoke 边界读取父窗是否仍最小化，为本次确认单独登记租约；服务启动准备的租约不能代替它。

- 对话框关闭后，有界观察实际父窗。若观察到本次确认使其还原，则仅请求一次非激活最小化，并读回最小化、正常位置及原普通/最大化还原模式。
- Allow 没有发出工具的 `SW_RESTORE` 请求；若观察区间内父窗始终最小化，记录 `unchanged=true`，不凭空恢复或补发最小化。此规则不适用于服务启动已经排队、尚未确认执行的恢复请求。
- 调用前用户已经恢复的窗口不被重新最小化。HWND、PID/创建代次、生命周期标记或几何变化时 fail-closed；纯标签变化仅观察。不重设基线，不重放 Allow。
- `consentWindowPreparation` 保留实际收尾结果；`consentFocusActive=false` 只证明区间已结束，不等于窗口原状已确认。

## 显式 restart 的停止读回

协议 stop 发出后只释放自己的连接一次，再独立确认原生工具栏关闭且监听消失。断连不证明停止完成，也不触发第二次 stop 或原生关闭回退。

最小化窗口的 UIA 工具栏可能暂留旧的开启标签。仅在显式 restart 已授权、当前监听已经消失且目标仍最小化时，允许一次 `prepareOnly` 启动准备：沿用精确窗口租约临时恢复并还原最小化，以刷新原生状态；此分支不打开面板、不调用服务开关。随后仍须读回工具栏关闭和无监听，才能真正启动新代服务。观察及原生请求各自有界，不能用端口关闭替代工具栏证据。普通 stop 不借用这项启动准备权限。

## 实机验收

本节命令记录维护机上的验收方式。按本次仅发布代码和文档的范围，下面的 `scripts/test-minimized-*.mjs` 及其验收辅助文件未提交；新克隆的仓库不包含这些本地维护脚本。

先 `status` 重新发现已有 Nightly 的目标 HWND。以下维护脚本只操作新建、证明归属的工作窗口；不刷新或读取用户网页正文，也不发送翻译请求。默认 `npm test` 不运行这些桌面脚本。

```powershell
# 已开服务：最小化下的默认 run、DOM 更新、页面截图、重新连接与精确清理。
node.exe scripts/test-minimized-nightly.mjs <本次实测HWND>

# 原最大化状态：只测最大化后最小化的位置元数据，不起停共享服务。
node.exe scripts/test-minimized-cold-start.mjs <本次实测HWND> --placement-only maximized

# 维护授权下真正关闭重开 Remote Control；Firefox 进程不重启。
node.exe scripts/test-minimized-cold-start.mjs <本次实测HWND> --native-cold-start normal
node.exe scripts/test-minimized-cold-start.mjs <本次实测HWND> --restart-service normal
node.exe scripts/test-minimized-cold-start.mjs <本次实测HWND> --restart-service maximized
```

冷启动运行须分别验证：原服务确实关闭、新代服务监听、本次原生 Allow/握手、目标恢复原最小化状态、正常位置/还原模式不变、实际 DOM/页面图像、owned 页/窗口消失，以及最终服务开关符合运行前状态。一次只持有自己的独占会话，停止请求发出后不回退或重发。

最小化截图使用页面捕获，并实际打开图像检查；系统窗口捕获可能为空白或旧帧，编码成功不算图像通过。页面上自写的 PASS 字样也不能代替独立 Win32 状态、归属与整次收据。

### 重新连接的身份边界

Nightly 160 的 BiDi context 与 clientWindow UUID 可能随会话重新分配。旧 scoped Page 在断线后继续失效，不能更换其连接并冒充从未断线。

维护夹具保留原来的原生生命周期标记、浏览器代次及 Gecko browserId；重新连接时，通过 Chrome `nsIBaseWindow.nativeHandle` 对应已核验 HWND，再由实际单个 XUL browser 映射当前 NavigableManager/WindowManager 的协议 ID，前后重验原生归属。旧 ID 和新 ID 分开记录；不凭 URL、标题或“多出来的一个页面”猜测对象，不把这项可信维护能力暴露给普通任务。

失败时保留原运行，不将后来的恢复收据改写成最初整次通过。精确回收流程与私有收据以当前脚本和 [验证记录](../VALIDATION.md) 为准。

### 完整离线回归

使用 `npm test`；当前脚本在测试文件 glob 之前设置单个测试 worker，避免 Windows 原生夹具与 PowerShell 编译竞争造成启动/IPC 超时。并发参数需位于文件路径之前，不能以向 npm 命令末尾追加参数来假定运行器已串行。临时目录使用调用环境显式提供的 scratch，并在同一调用中核对原生进程实际收到的 TEMP/TMP；旧失败日志保留，串行通过不改写先前失败。
