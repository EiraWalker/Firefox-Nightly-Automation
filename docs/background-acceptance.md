# 后台页面验收

[返回使用参考](reference.md)

在现有 Nightly 中核验页面实际行为或排查内部页导航时读取本文件。`run --task` 默认提供独立工作窗口和 `workspace.page`；目标 URL、扩展 ID、业务断言和私有收据路径由当前任务提供。窗口归属与并发检查契约见[独立工作窗口](task-workspace.md)。

## 连接与内部页

先检查 `status`，复用已有浏览器。`about:` / `moz-extension:` 导航被明确拒绝时，检查新进程是否通过默认启动器获得 system access，流程见[默认启动权限](reference.md#默认启动权限)。会话重置不改变进程启动权限。

需要正常退出重开时，先确认当前任务已有重启授权，检查可能丢失的草稿、生成和待发任务，按消费项目的数据保护要求备份，再正常退出并等待实际进程结束。随后从默认启动器打开并核对会话恢复及实际内部页访问。已有授权持续有效；没有重启授权时，报告这一前置条件。

原生 Allow 暂未启用时，工具在同一次连接的超时内等待。控件诊断、确认归属与失败处理见[原生控件诊断](reference.md#原生控件诊断)。不要为此重新建立连接或清除共享会话。

## 创建并识别自己的测试窗口

1. 使用 `workspace.page`，不枚举或接管用户原标签。工具已完成独立窗口创建和原生/BiDi 归属登记。
2. 按当前授权导航工作页，核对完整 URL、标题和就绪条件。扩展内部地址应来自本次已授权发现或扩展清单，不复用另一 profile 或旧会话的 UUID。
3. 测试消息、表单输入和事件仅发送给自己的工作页。需要的 API 超出任务范围接口时，先明确增加受归属限制的能力，不绕回全局连接。
4. 返回业务结果，交由 `run` 的 `finally` 关闭工作窗口和释放自己的连接；保留用户原窗口、浏览器进程和预先开启的服务。

工作窗口默认后台创建且不最小化；执行中最小化不再阻断 DOM 和页面截图，原生启动准备及正常位置校验见[最小化窗口](minimized-windows.md)。用户在其他窗口正常操作不是失败条件；工作窗口身份和受保护状态仍需核验。任务不重置已锁定的全局基线，原始全局变化继续报告。视频观看资格仍需检查真实可见性，不能由创建参数或工具操作成功推断。

## 导航超时后的就绪核验

`page.goto()` 超时可能发生在文档已加载之后。保留原错误，在同一个 Page 上核对当前完整 URL、`document.readyState` 以及任务真正需要的 DOM/API。只有目标身份和全部业务就绪条件都满足，才可继续，并在私有收据中标明导航超时及补充检查结果。

明确的权限拒绝、页面关闭、目标不唯一或业务条件不满足仍是失败。不要盲目刷新、重放表单或创建另一连接。扩展管理页能显示，也不等于其存储/API 已可用；用户脚本源文件已构建，也不等于管理器已保存或新文档已加载该版本。

### 内部页命令支持差异

内部页导航及扩展 API 调用通过后，其他 BiDi 命令仍可能不支持该上下文。当前 Nightly 已出现 `browsingContext.activate` 对 privileged scope 返回 `unsupported operation`：这不是缺少启动权限的证据，不据此重启浏览器、重置会话或反复建连。先确认失败的具体命令及上下文类型，选用有真实验收证据的受支持路径；没有可用路径时保留该业务步骤未完成。

需要用户手势的扩展操作另行核验实际事件及浏览器权限确认；脚本函数执行成功、`userActivation` 参数或合成 click 都不能单独证明权限已经授予。最终仍须通过扩展 API 读回所需权限及业务结果。

## 输入与图像证据

已授权的鼠标拖动验收使用 Puppeteer `page.mouse`，例如在已确认的正文坐标内：

```js
await page.mouse.move(x, y);
await page.mouse.down({button: 'middle'});
try {
  await page.mouse.move(x, y + deltaY, {steps: 5});
} finally {
  await page.mouse.up({button: 'middle'});
}
```

先记录真实滚动容器的位置和范围，选择仍有移动空间的方向。观察移动量、按住期间的光标、松开后的光标及后续移动是否停止滚动。记录事件的 `isTrusted`、`button`、`buttons` 与是否被阻止，可区分浏览器输入和 `dispatchEvent`；浏览器可信输入的通过结果不能代替物理鼠标手感验收。

截图写入消费项目忽略的 `.local/`，实际打开图像检查。被遮挡或最小化窗口的系统捕获可能只有灰色或旧帧；成功编码不证明页面可见。需要页面内容证据时可使用 `page.screenshot()`，同样检查图像与目标身份。截图可能包含正文与用户侧栏，只保存获准的私有图像，不提交仓库；不记录密码、cookie、授权头或令牌。

## 完成判定

| 层次 | 必须取得的证据 |
| --- | --- |
| 连接 | 实际握手；需要确认框时 seen/invoked/closed 完整 |
| 安装或更新 | 管理器/扩展中的实际版本、启用状态及必要的持久化状态 |
| 页面运行 | 新文档中的目标身份和运行版本或行为特征 |
| 业务 | 用户要求的操作产生可观察结果，必要时查看截图 |
| 整次运行 | CLI 退出码、ok、最终桌面守卫和归属清理结果 |

业务步骤完成后，最终守卫仍可能返回 `F_DESKTOP_CHANGED`。保留分步证据，报告已完成操作与最终失败原因；整次 run 不能记为通过，也不能自动重放已经产生副作用的任务。原始失败字段与阶段收据的解释见[输出和失败处理](reference.md#输出和失败处理)。
